## Android build path and blockers

Build command shapes from the checked-in Expo/Gradle configuration (not run):

- Debug APK: `cd upstream/ringee-mobile && npm ci && cd android && ./gradlew assembleDebug` (the Android project is checked in and the debug signing config is in the Android app Gradle file). `npm run android` invokes `expo run:android` for a device/emulator build.
- Release APK: same prerequisites, then `./gradlew assembleRelease`.
- Release AAB: same prerequisites, then `./gradlew bundleRelease`.
- EAS internal preview APK: `eas build --platform android --profile preview`; the profile explicitly sets `android.buildType: apk`. The production EAS profile omits `android.buildType`, so this source does not establish whether the resulting artifact is APK or AAB; any claim that it defaults to AAB is an inference that requires checking the active EAS behavior ([eas.json:11-19](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/eas.json#L11-L19)).

Build prerequisites include Node/npm for the Expo/React Native bundle and native autolinking; network access for Gradle wrapper/dependencies; a JDK compatible with the pinned Gradle 9 wrapper; Android SDK/build tools/NDK for local Gradle builds. SDK/NDK versions are consumed from Gradle root-project properties by the app configuration and are not assigned in this checked-in app Gradle file ([gradle-wrapper.properties:1-7](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/android/gradle/wrapper/gradle-wrapper.properties#L1-L7); [android/app/build.gradle:84-94](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/android/app/build.gradle#L84-L94)).

Configuration/deployment blockers:

- `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY` is required at app startup; missing it throws immediately ([app/_layout.tsx:48-54](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/app/_layout.tsx#L48-L54)).
- `EXPO_PUBLIC_RINGEE_API_URL` feeds `API_URL`, with no nonempty fallback ([constants/Config.ts:1-5](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/constants/Config.ts#L1-L5)). It must be set to the intended backend origin; endpoint `/api` prefix behavior needs to match the deployed host/gateway (the client appends route paths directly).
- Native voice login requires `EXPO_PUBLIC_TELNYX_SIP_USERNAME` and `EXPO_PUBLIC_TELNYX_SIP_PASSWORD`; the provider logs in from those values and places calls through Telnyx ([constants/Config.ts:30-35](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/constants/Config.ts#L30-L35); [TelnyxVoiceProvider.tsx:216-236](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/lib/voice/TelnyxVoiceProvider.tsx#L216-L236)). `EXPO_PUBLIC_*` values are app-bundle configuration, so putting a reusable SIP password there exposes it to app users. The mobile source has a backend `/webrtc/credentials` client function, but this provider does not use it. This is a release security blocker until credential issuance is short-lived/user-scoped or the voice flow is intentionally disabled.
- `android/app/build.gradle` configures the `release` variant with the committed debug signing config (`debug.keystore`, alias/password `android`) and explicitly warns a production keystore is needed ([android/app/build.gradle:100-119](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/android/app/build.gradle#L100-L119)). A release built from this config is not ready for production distribution; supply protected release signing credentials/configuration. EAS project ID exists, but EAS account/build credentials, push credentials, and store credentials are external state and unknown ([app.json:87-91](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/app.json#L87-L91)).

No APK/AAB was built, so build success is unknown.

## Tenant boundaries and data surface

Mobile API calls send Clerk bearer tokens; mobile code does not send a client-controlled `userId` or `organizationId` as the ownership claim in these requests. In the backend snapshot, mobile calls/contacts use `createOwnershipContext(user)` and owner-aware service/read methods; mutation paths fetch visible records before mutation ([mobile.controller.ts:63-88, 162-189, 286-324](https://github.com/ringee-io/ringee-app/blob/b04a4b889a9c827e76f64574f6f3b2f1c5f79241/apps/backend/src/api/routes/mobile.controller.ts#L63)). Callbacks, meetings and reminders likewise create ownership context before reads/writes (refs in table). The sibling repo’s [`AGENTS.md:62-72`](https://github.com/ringee-io/ringee-app/blob/b04a4b889a9c827e76f64574f6f3b2f1c5f79241/AGENTS.md#L62-L72) documents the required personal scope (`userId` plus `organizationId: null`) vs organization scope (`organizationId`); this audit only confirms route usage of ownership-context abstractions, not every repository query or runtime isolation behavior. Push/preferences are user-scoped in the controller.

The mobile UI/API surface includes contact list/search/detail and recent call history, contact notes, call history/detail/outcomes/call notes, callbacks, meetings, reminders, missed-call list, call transcription/recording metadata, push registration/preferences, and outbound calling. Mobile contact detail DTO includes `recentCalls`, contact `notes`, `upcomingCallback`, and `upcomingMeeting` ([contacts.ts:35-49](https://github.com/ringee-io/ringee-mobile/blob/2d098a1e5a7413fcdf8fde0157afa1864d8f443c/lib/api/contacts.ts#L35-L49); backend mapping [mobile.controller.ts:286-324](https://github.com/ringee-io/ringee-app/blob/b04a4b889a9c827e76f64574f6f3b2f1c5f79241/apps/backend/src/api/routes/mobile.controller.ts#L286-L324)). Call notes are stored as contact notes when a call is linked to a contact; otherwise backend appends them to the call outcome note ([mobile.controller.ts:210-231](https://github.com/ringee-io/ringee-app/blob/b04a4b889a9c827e76f64574f6f3b2f1c5f79241/apps/backend/src/api/routes/mobile.controller.ts#L210-L231)). No source evidence of device address-book import/access was found; “contacts” here are Ringee backend contacts, not confirmed phone contacts integration.
